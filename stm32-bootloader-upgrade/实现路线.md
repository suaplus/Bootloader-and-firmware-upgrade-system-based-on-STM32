# 四步跑通（每步都有明确验收标准）

代码已经全部给出，按下面顺序做，每一步都能独立验证，出问题也容易定位。

---

## 第 1 步：内部 Flash 读写（约半天）

**做什么**：新建一个最小 CubeMX 工程（USART1 + SPI1 + GPIO，**不用开 I2C**），把 `platform/bsp_flash.c/h`、`platform/bsp_at24c02.c/h`、`common/crc_utils.c/h` 加进去，在 `main()` 里做一次实验：

```c
uint8_t w[16] = "hello boot";
flash_erase_region(APP_B_START_ADDR, 2048);      /* 拿 B 区当靶子，别动 Bootloader */
flash_write(APP_B_START_ADDR, w, sizeof(w));
uint8_t r[16];
flash_read(APP_B_START_ADDR, r, sizeof(r));      /* 断点看 r 的内容 */
```

**验收**：`r` 与 `w` 一致；擦除后再读全为 `0xFF`；`flash_crc32()` 结果与电脑端算的一致。

---

## 第 2 步：Bootloader 跳转（1 天，最关键）

**做什么**：
1. Bootloader 工程：`boot_main.c` + `boot_jump.c` 编进去，`BOOT_SIZE` 记得是 24KB，IROM 起始 `0x08000000`。
2. APP 工程：随便写个 LED 闪烁 + 串口打印，IROM 改 `0x0800C000`，`main()` 第一行加 `SCB->VTOR = APP_A_START_ADDR;`。
3. 先用 Keil 分别下载两个工程，再单独复位。

**验收**：串口先打印 `[BOOT] ...` 再打印 `[APP] ...`，LED 开始闪 —— 说明栈、向量表、跳转全部正确。
**如果失败**：99% 是 VTOR 没设 或 Keil IROM 没改，先查这两项。

---

## 第 3 步：外挂存储（1 天）

**做什么**：
- `w25q_board_init()` 先把 PA4/PA8 拉高，再读 ID，串口打印，应为 `0x00EF4017`；
- 写一段 4KB 数据到 `0x000000`，读回比对，`w25q_crc32()` 与电脑计算值一致；
- `at24c02_self_test()` 返回 0（已在最后 4 字节做写读回比对），再写入 `fw_param_t`，断电重新上电后 `fw_param_load()` 返回 0。

**验收**：W25Q64 ID 正确、读回数据一致；AT24C02 断电后参数仍在（`magic` 与 `crc` 校验通过）。
**如果 EEPROM 全 0xFF**：先确认 PA2/PA3 在 CubeMX 里是 **开漏输出 + Pull-up**，这是软件 I2C 的硬性要求。

---

## 第 4 步：完整升级链路（2~3 天）

**做什么**：
1. APP 工程里接上 `fw_update.c` + `bsp_uart_dma.c`，主循环加 `bsp_uart_poll();`（轮询搬运 DMA 数据，不用 IDLE 中断）。
2. 生成 `app.bin`：`fromelf --bin --output app.bin .\Objects\app.axf`。
3. 运行 `python tools/fw_send.py --port COM3 --file app.bin --version 1.1`。
4. 观察串口：收包 → `[UP] verify...` → 自动复位 → `[BOOT] migrate ...` → 新版本 APP 启动。

**验收**：升级后串口打印的版本号变成 1.1；升级中途拔电再上电，设备仍能起旧固件（暂存区被丢弃）。

## 第 5 步（可选，加分项）

| 功能 | 改动点 |
| --- | --- |
| 恢复出厂实测 | 故意把 A 区擦掉（`flash_erase_region(APP_A_START_ADDR, ...)`），复位后应停住等待串口下载 |
| 断点续传 | `fw_update.c` 里记录已写最大 offset，START 时回传，上位机从该 offset 继续 |
| CAN / LoRa / 4G | 只替换数据来源与 ACK 发送回调，`fw_update_feed()` 不动 |
| 上位机 OTA 服务器 | MQTT 下发分片，payload 直接喂 `fw_update_feed()` |

---

## 代码里已经埋好的"可讲点"

- `fw_proto.c` 的流式状态机：半包、粘包、丢字节都能自愈，不是简单的 `memcmp` 判断。
- `bsp_uart_dma.c`：DMA 环形缓冲 + IDLE 中断 + 软件环形队列，中断里不做重活。
- `fw_param.c`：参数主备双份 + CRC，主份坏自动用备份修复。
- `boot_main.c`：升级前备份 A→B、启动计数 3 次失败自动回滚、A 区非法落回 Reset。
